# Review of feat/collab-ui a5966b5 (slice 1) — lens: correctness + regressions (Codex gpt-6.1-sol, 2026-10-22 ~16:05 UTC, static + bun tests, no server)

1. **High — `app/components/mailclient/composition/ComposeOrchestrator.tsx:1090`: opening another composer re-enables duplicate delivery.** After a successful send with warnings, starting a forward or draft edit immediately clears `deliveredRef` and the receipt, before asynchronous hydration replaces the old compose fields. While hydration is pending, Send can submit the already-delivered message again. **Fix:** preserve the delivery guard until the new compose session has initialised successfully; reset guard and fields together.

2. **Medium — `app/hooks/useThreadCollab.ts:65`: navigating away prevents rollback propagation.** Change thread A optimistically, select B, then let A's PATCH fail. `accept(previous, A)` repairs the hook cache but skips `onUpdate`, leaving A's list chips and `threadCollabById` optimistic. Successful background mutations similarly skip count/filter refresh through the guard at line 181. **Fix:** publish settled updates for their originating account/thread independently of the selection; guard only the selected-pane state.

3. **Medium — `app/components/MailClient.tsx:2834`: authoritative list refreshes do not refresh collaboration state.** Another member changes the selected thread, then a mailbox refresh returns newer `Message.collab`. Rows can show the new status while the bar keeps the old status/count indefinitely because the hook's inputs have not changed. Resync merges are worse: remapping can preserve `updatedAt`, and `CollabRowBadges.tsx:22` prefers the stale cached value on equality. **Fix:** reconcile or invalidate both caches on authoritative refresh/resync and reload the selected thread's comments/activity.

4. **Medium — `ComposeOrchestrator.tsx:1053`: detached Sent-copy warnings can disappear unseen.** Open detached compose for mailbox A, switch the parent to B, then send with `sentCopy: "failed"`. The child closes automatically while `MailClient.tsx:5094` ignores A's event; the warning has no persistent visible destination. **Fix:** retain warning receipts until acknowledged, or reliably display and persist mailbox-labelled warnings regardless of the parent's selected mailbox.

5. **Medium — `ComposeOrchestrator.tsx:1042`: an old send failure can replace a new composer with a sent receipt.** Send A successfully, open and begin writing B while A's mailbox refresh is pending, then let that refresh reject. A's catch handler installs delivery warnings into B's session, hides B's fields and disables its autosave. **Fix:** capture the compose session version at send time and guard subsequent compose-state changes against that version; an obsolete refresh failure should emit only a notice.

6. **Medium — `useThreadCollab.ts:117`: read authorization failures leave cached collaboration editable.** Revisit a cached thread after mailbox membership was revoked. Its GET returns 403, but cached notes/state/members stay available and the stale editor role keeps mutation controls enabled. **Fix:** invalidate the affected account's collaboration cache and disable controls on read authorization denial, without logging out globally; keep readable state for an insufficient-role write rejection.
