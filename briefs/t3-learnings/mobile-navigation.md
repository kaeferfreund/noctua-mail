## Transferable ideas, ranked by gain versus risk

Expected gains below are hypotheses for Noctua. T3 percentages must not be carried over as Noctua forecasts. Items 1–3 and 9 are concrete input to the current deep-link implementation; the rest can follow existing switch work or wait until after go-live.

### 1. Make URL navigation and the existing mobile history share one transition contract

- **Technique / sources:** Separate “open destination”, “Back”, and “select list”; update visible selection and history together. Learn from [#21033](https://github.com/pingdotgg/t3code/pull/21033) and the visible-list/stale-route defect in [#22526](https://github.com/pingdotgg/t3code/pull/22526).
- **Noctua evidence:** `app/hooks/useMobileNavigation.ts:11` already pushes a `noctuaMobileView` entry, consumes `popstate`, and supplies header Back; `app/hooks/useMobileOverlayHistory.ts:28` consumes overlay pops in capture phase and defers navigation while a sheet's programmatic Back settles. `app/components/shell/AppShell.tsx:68` owns the hook. Thus the deep-link brief's blanket “phone Back leaves the app” description is incomplete for this reference: a mobile Back layer already exists, without canonical URLs or full Forward restoration.
- **Implementer hint:** Let the new navigation hook own place history; adapt the mobile view hook to that owner rather than adding a second push on message selection. Keep overlay interception/deferral, merge existing `history.state` fields, and make header Back invoke the same operation as browser Back. On an external cold message link, explicitly establish a same-mailbox list predecessor if required, once; do not infer an app-owned predecessor from `history.length`. Forward must reopen the reader. A cancelled native/browser swipe must not clear selection early.
- **Gain / risk:** High correctness and predictable one-step return at 390 px; medium integration risk because duplicate pushes/listeners can produce empty steps or lose sheets. **Overlap:** deep links.
- **Verify:** At 390 px: list → mail → nested sheet → Back closes sheet → Back shows list → Forward reopens mail. Repeat opening another mail, interrupted account switch, refresh/direct link, and cancelled iOS edge swipe. Assert URL, visible pane, and selected account/message after each step; no extra switch requests.

### 2. Resolve deep links through target-local hydration with explicit terminal states

- **Technique / source:** [#11502](https://github.com/pingdotgg/t3code/pull/11502) distinguishes “not here yet” from “unavailable”, based on the destination's own data lifecycle.
- **Noctua evidence:** `app/components/MailClient.tsx:4219` reads launch params once; `:4718` retries pending external-message jumps; `:4697` only opens a local ID once it enters `messageById`; `:5007` has an authorized detail resolver. A mail outside loaded pages can be absent from the list without being deleted. The existing resolver collapses HTTP error classes to null, which is insufficient to distinguish offline, denied, and missing in a new route lifecycle.
- **Implementer hint:** Use a destination token and explicit phases: parse → authenticate → validate membership/switch → resolve message/folder → show reader. Keep pending destination through auth/bootstrap; do not overwrite its URL with the default mailbox during initialization. Resolve an off-page local ID through the authorized account detail route rather than paging an entire inbox. Only apply responses matching the latest destination; distinguish 401, 403, 404, and network error. A terminal denial/deletion ends loading; unrelated account sync does not prolong it. Reuse the account switch controller's latest-wins behavior.
- **Gain / risk:** High reliability on slow phones and cold PWA launches; low–medium risk with a small explicit lifecycle. **Overlap:** deep links; aborting stale detail loads already appears in switch-work cluster G—coordinate rather than duplicate it.
- **Verify:** Delay auth, folders, detail and list independently; link directly to a message beyond page 1; return 403/404/offline; navigate A→B→A and pop Back before B's detail completes. No false “missing” flash, indefinite spinner, or stale reopening.

### 3. Restore semantic anchors; explicit deep-link targets and user scrolling win

- **Technique / sources:** [#12144](https://github.com/pingdotgg/t3code/pull/12144) stores row ID, offset within row and disclosure state; [#4867](https://github.com/pingdotgg/t3code/pull/4867) shows how late measurement retries can fight a reader's drag.
- **Noctua evidence:** `app/components/MailClient.tsx:2708` captures one raw list `scrollTop`; `lib/ui/useReaderFocusPlacement.ts:13` restores it only when desktop reader focus changes (`MailClient.tsx:2683`). Reader selection scroll is scheduled after a 220 ms collapse settle (`MailClient.tsx:4758`, `mailclient/constants.ts:20`). `app/components/HtmlMessage.tsx:530` measures iframe height asynchronously, again after assets/fonts (`:626`). Browser window scroll restoration cannot restore these inner panes.
- **Implementer hint:** Store bounded, lightweight list anchors by account + full list/query key, and reader anchors by account + thread/message. Save stable row/message ID, intra-row offset, pixel fallback and relevant expansion state; use history-entry identity where two visits need different positions. Precedence: new explicit URL message target → saved Back/Forward anchor → normal default. Expand the linked message before positioning; remeasure after panel reveal and HTML layout. Cancel restoration on touch/wheel/pointer/scroll keys or destination change; avoid repeated smooth scroll for history navigation and honor reduced motion. Bound any settle/retry work.
- **Gain / risk:** High perceived continuity on long lists/HTML conversations; medium layout risk. **Overlap:** deep links; existing desktop reader-focus placement is reusable behavior, not a new parallel system.
- **Verify:** Scroll deep into a folder, open an older conversation message, switch folders/accounts and Back; retain the same row/reading line. Repeat with delayed images, collapsed quotes, font size changes and orientation. Touch-scroll while restore is pending: no later snap-back. New link target must beat a previously saved reader position.

### 4. Keep the shell mounted and reuse only the destination's own warm content

- **Technique / sources:** Combine [#11169](https://github.com/pingdotgg/t3code/pull/11169) with its corrective follow-up [#21560](https://github.com/pingdotgg/t3code/pull/21560). Keep structural continuity and target-keyed snapshots; never label old content as the new destination.
- **Noctua evidence:** `app/components/shell/ShellPanes.tsx:98` retains both panes; mobile CSS hides one (`ShellPanes.module.css:48`). `app/components/mailclient/useThreadContent.ts:75` already maintains a bounded thread cache. `MailClient.tsx:2675` rejects a view message belonging to a different active account. `mailclient/useMessageData.ts:107` clears list state for a new key.
- **Apply:** Preserve the mounted shell and lightweight list state. If introducing warm list/reader restoration, key it by authorized account + destination identity; show destination-local loading on a cold miss. Keep pending feedback distinct from committed account selection, and keep controls bound to the data actually displayed. Retain membership/revocation invalidation; do not add a second body cache just to avoid a flash.
- **Gain / risk:** Medium–high perceived speed for repeated visits, unmeasured here; medium memory/staleness risk. **Overlap:** switch work, especially pending-row feedback B and scoped-cache invariants; deep links can reuse it.
- **Verify:** Hold B's network response while A has distinctive synthetic content; B's header/URL must never accompany A's body. Warm A↔B, rapid A→B→C, and membership revocation must preserve target identity and existing authorization behavior.

### 5. Treat revealing a hidden mobile pane as a viewport change

- **Technique / sources:** [#18963](https://github.com/pingdotgg/t3code/pull/18963) and [#4867](https://github.com/pingdotgg/t3code/pull/4867) illustrate stale geometry and estimated/measured mismatch. Transfer the geometry invariant, not the native library patch.
- **Noctua evidence:** The list stays mounted but is `display:none` in phone reader mode (`ShellPanes.module.css:48`). `app/components/mailclient/messagelist/VirtualizedList.tsx:39` samples height on mount, scroll and **window** resize, with a 720 px fallback (`:82`); it does not observe the scroll element's resize/reveal. A hide/reveal need not fire a window resize. This is a code-level risk, not a reproduced defect.
- **Apply:** Observe the existing scroll viewport or trigger one measurement after mobile pane reveal; restore its anchor only after nonzero geometry. Do not overwrite saved visible position with measurements taken while hidden. Keep `HtmlMessage`'s existing ResizeObservers and requestAnimationFrame coalescing rather than adding per-image scroll corrections.
- **Gain / risk:** Medium resilience to blank/wrong virtual windows after Back, low–medium risk. **Overlap:** deep links for reveal/restore sequencing; otherwise none.
- **Verify:** At 390 px, scroll list far down → open mail → change viewport via keyboard/orientation → Back. Visible rows must fill the actual pane with stable position and no synthetic window-resize event required.

### 6. Budget retained bodies and hidden reader work separately from navigation state

- **Technique / sources:** [#13686](https://github.com/pingdotgg/t3code/pull/13686) retains cheap shell subscriptions while releasing hidden full-detail retention. [#16296](https://github.com/pingdotgg/t3code/pull/16296) demonstrates native memory pressure, but its explicit GC is not applicable to a web app.
- **Noctua evidence:** `mailclient/constants.ts:23` limits cache to **50 threads**, not bytes; `mailclient/utils/threadContentCache.ts:18` evicts by thread insertion/update order. `mailclient/message/ThreadView.tsx:69` renders every conversation card. Compact collapsed rows already avoid mounting their body subtree (`ThreadMessageCard.tsx:565`); expanded HTML creates iframe documents/observers (`HtmlMessage.tsx:488`). Both shell panes remain mounted even when CSS-hidden.
- **Apply:** First measure 50 large HTML conversations, JS retention and iframe counts; then bound retained body payload by size as well as count while keeping anchors/headers cheap. After an idle delay in list mode, release hidden heavy reader content if measurements justify it, preserving drafts, selection and scroll metadata. Do not blindly unmount the whole shell/list. Browser lifecycle handling should release references and clean observers, not invoke Hermes GC. No offline body persistence is needed for this improvement.
- **Gain / risk:** Potentially high phone memory savings; medium reload/position risk, no heap figures available. **Overlap:** backlog; payload slimming K is already parked/audit-gated. A client cache budget is separate from changing server payload contracts.
- **Verify:** Synthetic large HTML/attachment-heavy threads; 50 visits plus repeated reader/list cycles. Compare retained objects/documents before and after idle/GC where tooling permits; test background/resume and process-killed PWA reload. Drafts and linked message recovery must survive intended retention policy.

### 7. Keep URL state and live mailbox activity from invalidating the whole screen

- **Technique / sources:** Primitive route selectors [#20837](https://github.com/pingdotgg/t3code/pull/20837), stable row callbacks [#21255](https://github.com/pingdotgg/t3code/pull/21255), quiet selection state [#20963](https://github.com/pingdotgg/t3code/pull/20963), and row-local context [#21123](https://github.com/pingdotgg/t3code/pull/21123).
- **Noctua evidence:** `MailClient.tsx:5393` creates the collaboration context value at the shell boundary; `mailclient/message/MessageViewOrchestrator.tsx:754` rebuilds an enhanced message map during render. These are inspectable invalidation boundaries, not measured bottlenecks. The new deep-link hook will run beside this large state owner.
- **Apply:** Depend on primitive navigation IDs/options, memoize parsed route descriptors explicitly if needed, and serialize only when semantic place changes. Distinguish applying `popstate` from publishing UI navigation so the same URL does not reenter switch/load effects. Avoid full `Message` objects, fresh route objects or scroll offsets as bootstrap dependencies. Preserve unchanged row/message references and pass stable callbacks. Do not copy the LegendList context fix unless a profiler shows an equivalent outgoing-row problem in Noctua's different virtualizer.
- **Gain / risk:** Medium CPU/interaction gain during background sync; low risk for narrow identity fixes. **Overlap:** deep links for route stability; switch work A/H for list identity/rendering. Translator/address parsing fixes are already covered and are not reproposed.
- **Verify:** Profile a production build at 390 px during SSE traffic, search typing, same-place replaceState and open/close menus. Count row/HTML renders and account bootstrap/list calls; same destination must not reload or rebuild the reader.

### 8. Prefer immediate, cheap loading feedback and stable geometry over elaborate skeletons

- **Technique / sources:** [#19654](https://github.com/pingdotgg/t3code/pull/19654) → [#21480](https://github.com/pingdotgg/t3code/pull/21480) is a useful reversal: keep cache reuse/height reservation, remove an expensive, short-lived layout skeleton/fade. [#19292](https://github.com/pingdotgg/t3code/pull/19292) warns that decorative activity must not starve Back; its specific native cause does not apply to CSS.
- **Noctua evidence:** `ThreadMessageCard.tsx:527` already displays a compact status/skeleton only if content hydration is needed; `ThreadMessageCard.module.css:364` animates CSS opacity and `:582` handles reduced motion. `HtmlMessage.tsx:530` already coalesces size updates. IMAP streaming already stops in hidden documents (`useSyncController.ts:1383`), so a proposal to add that globally would be duplicate work.
- **Apply:** Keep current lightweight feedback; use it for cold deep-link resolution without artificial minimum delay/fade. Preserve known height where valid for the same body/width/font settings. Do not derive placeholder layout by parsing arbitrary mail DOM. T3's signed-URL result applies to remote HTML artifacts; Noctua uses sanitized `srcdoc`, so do not transplant URL-signing or private mail HTTP-cache rules. Avoid JS-per-frame skeleton updates and suspend unnecessary hidden reader activity if observed.
- **Gain / risk:** Medium perceived responsiveness, low risk; server/network time unchanged. **Overlap:** switch pending feedback B; otherwise backlog/none for new deep-link loading state.
- **Verify:** Fast warm open, cold open with delayed detail, and heavy HTML while pressing Back; compare time to first feedback, correct content and layout shift. Reduced motion, background/resume, and warm same-message refresh should not flash placeholders over usable content.

### 9. Use one canonical target/serializer for Copy link and both PWA notification paths

- **Technique / sources:** [#22153](https://github.com/pingdotgg/t3code/pull/22153) shares target resolution between open and context-menu actions; [#11502](https://github.com/pingdotgg/t3code/pull/11502) supplies the cold-entry lifecycle.
- **Noctua evidence:** `app/components/mailclient/message/MessageMenu.tsx:243` is the existing responsive more menu. `public/sw.js:146` creates legacy account/message URLs; `:235` either focuses an existing client and posts `noctua:notification-open` or opens a new window. `MailClient.tsx:4246` handles that warm message path separately from URL mount parsing; its payload includes `url`, but the current handler uses message/account fields. `app/manifest.ts:10` starts the installed app at `/` and already supports mailto launches.
- **Implementer hint:** Centralize parse/serialize/resolve once. Copy a canonical absolute URL from the message's own account/message identity, including pop-out context; do not copy the current unrelated folder URL. Preserve legacy notification IDs through an explicit adapter (external Message-ID versus local row ID). Route warm SW messages, cold URLs, popstate and in-app opens through the same latest-wins entry point; warm notification opens must update the canonical address too. Keep draft content out of URLs. Prefer the existing explicit “Link kopieren” menu; real links can additionally retain native long-press affordances without a bespoke gesture system.
- **Gain / risk:** High functional coverage, low–medium integration risk. **Overlap:** deep links, directly in scope now; no new PWA/offline architecture required.
- **Verify:** Copy from list/reader/pop-out → fresh authenticated or login-required context; notification with open app and with no app client; legacy links, mailto, off-page message, moved/deleted message. Same destination and sensible Back in all cases. Test actual installed iOS/Android PWA separately: 390 px emulation alone does not establish OS link capture or lifecycle behavior.

### 10. For long-thread CPU, reuse unchanged derivations before adopting a new list library

- **Technique / sources:** [#19135](https://github.com/pingdotgg/t3code/pull/19135) caches unchanged prefixes at safe grouping boundaries, with full invalidation for changes affecting earlier grouping. [#22913](https://github.com/pingdotgg/t3code/pull/22913) shows that a cache can still be defeated by unrelated component updates and unstable output arrays.
- **Noctua evidence:** `mailclient/message/ThreadView.tsx:69` maps the conversation; `mailclient/messagelist/VirtualizedList.tsx:72` recomputes all offsets when item or height-function identity changes, although it only mounts the visible slice (`:93`). Virtualization bounds DOM, not all grouping/derivation CPU. `MailClient.tsx:2655` supplies thread-tree/flatten helpers to list derivation.
- **Apply:** After profiling, isolate pure visible-thread/group projections from URL, menu and sync-status state; reuse unchanged inputs/outputs. Only attempt incremental suffix recomputation where semantics permit it: mail threading can change earlier groups on late arrival, move/delete, date sort, topic or membership changes. Use complete invalidation for those cases. Do not adopt React Compiler settings or T3's native list package as a prerequisite.
- **Gain / risk:** Potentially high on very long histories, but lower priority than navigation correctness and medium–high grouping risk. **Overlap:** switch work H is already implementing forest/flatten/list passes; hand this evidence there, not a second optimization branch. Further work belongs in backlog unless profiling justifies it.
- **Verify:** Synthetic 1k/5k message sets with late replies, flag changes, deletions and grouping changes; compare incremental output against a fresh full derivation and profile input latency/long tasks on a phone. Measure application render/navigation separately from pure-function time.

## Five-line summary

1. Integrate canonical URLs with Noctua's existing mobile and overlay history; avoid duplicate entries and test Forward as well as Back.
2. Treat cold/off-page deep links as pending until target-local auth, mailbox and message resolution settle; latest destination wins.
3. Restore scoped row/message anchors after measurement, with explicit links and the user's own scrolling taking precedence.
4. Keep lightweight views warm, bound heavy content retention, and never display the outgoing mail beneath the incoming destination.
5. Reuse existing switch optimizations and simple feedback; T3's native-only mechanisms and qualified measurements are not Noctua performance guarantees.
