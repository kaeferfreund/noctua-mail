## 2. Go-live blockers (must-have, not yet designed)

## 3. IMAP login (input for the Better Auth design run, not a decision)

- **Recommended rule (analyst option A, verified):** a user may sign in with the password of their *login mailbox* = the single account with `ownerUserId = user.id`, `lower(email) = lower(imap.user) = user.email`, `imap.secure = true` and `imap.host` in `NOCTUA_IMAP_LOGIN_HOSTS` (unset = method off); member count is irrelevant and shared mailboxes can never authenticate anyone because their address is not the user's. Companions: generic 401, a mailbox-login limiter checked right before the IMAP call (credential checks bypass the connect breaker, `lib/mail/imapAuth.ts:20`), write-back only to that mailbox and only on success, revoke other sessions on every stored-password change of the login mailbox (login write-back, relogin, PUT, POST existing id), a max age for mailbox-password sessions, re-auth before enrolling any credential. Replaces the design's "exactly one member" rule (`doc:256-262`), which locks the owner out as soon as she shares her own mailbox read-only and protects nothing (TLS hostname identity is already enforced, `lib/mail/imapClientOptions.ts:426-470`).
- **Alternative B (IMAP only, no app-independent credential):** rejected; a netcup outage or login-rate block becomes "nobody can log in" (`lib/mail/imapAuth.ts:36-37` returns false on any error) and it undoes D1/§4.4 and the committed Stage 1 work (feat/team-auth `6fee1b8` has `lib/passwords.ts` and the §3.1 columns). Keep a provider-independent fallback credential for the admin in every variant.
- **Alternative C (keep the design: IMAP login only as a migration path for migrated installs):** acceptable only with blockers 3, 4 and 5 applied and §8/D3 stating plainly that new users never use IMAP login; under C both spouses end up with app passwords/passkeys anyway (signup requires a password, `doc:267-272`; the form has no mailbox fields, `doc:660-664`).
- **Porting note:** the analyst's `amr`/`iat < passwordUpdatedAt` mechanics assume the stateless sealed cookie (`lib/auth.ts:23-28`, `app/api/auth/me/route.ts:26-38`). With Better Auth server-side sessions the mechanism is "delete the user's other sessions"; the triggers and the eligibility rule carry over unchanged. Unverified assumption: netcup's IMAP login name equals the full address; if it is a mailbox id, compare `imap.user` against a stored per-user login name instead.

## 5. Cut-over runbook outline (deploy-runbook items, in order)

0. **POP3 pitfall first.** Record keep/delete mode of every MailPlus fetch entry. Noctua mirrors the netcup server state: an IDLE expunge deletes locally at once (`imap/stream/route.ts:323-336`), full and repair syncs delete rows whose UID vanished (`lib/syncOperation.ts:339-341,456-460`). Imported INBOX mail gets new POP3 UIDLs and would be fetched (and in delete mode deleted) again. Therefore: one last manual fetch at T0, disable every fetch entry and the admin POP3 switch *before* any INBOX import and before creating any Noctua account; never re-enable while imported mail sits in a netcup INBOX. Non-INBOX folders can be copied while MailPlus is live.
1. **Inventory table** `address -> {netcup mailbox | alias of X | forward to X}`, MailPlus shared mailbox -> netcup mailbox -> Noctua `account.email`/`account.name` -> members/roles. Rule: 1 MailPlus shared mailbox = 1 netcup mailbox = 1 Noctua account with both as members (5 MonkeyDent shared mailboxes vs 4 monkeydent.de addresses cannot map 1:1). `account.email` is the From, the id key and immutable (`lib/accountId.ts:3-7`, `doc:126,370`); `account.name` is both the sidebar label and the From display name sent to customers (`lib/mail/smtp.ts:37-40`), so name the two "Dev" mailboxes for both uses. Turn forwarders into real mailboxes where sending is needed; filter-only MailPlus mailboxes become folders of the parent; remove forwards from shared addresses into personal mailboxes; check the netcup mailbox quota.
2. **netcup per-mailbox prep.** `CAPABILITY` (UIDPLUS: without it draft saves fail after the APPEND and leave orphan drafts, `lib/drafts.ts:255-258`; SPECIAL-USE), `LIST "" "*"` (prefix, delimiter, Sent/Drafts names), create Sent/Drafts where missing; enable the Plesk spam filter with "move to Spam folder" (Noctua only recognises a Junk/Spam folder, `lib/specialFolders.ts:13-21`, and reads no spam headers); inventory and recreate MailPlus auto-replies/rules in Plesk (nothing in Noctua: no vacation/sieve code); probe ManageSieve on 4190; measure IMAP concurrency and login-rate limits with a script, remember the connect breaker (3 failures -> 30 s block per mailbox, `lib/mail/imapClientOptions.ts:29-31`) and that hidden tabs re-login every 5 min (`useSyncController.ts:1340-1346`, pool idle 60 s `connectionPool.ts:61`); list every phone client that also talks IMAP; `openssl s_client -connect <host>:993` must match the configured host (`imapClientOptions.ts:426-470`).
3. **Server prep.** `NOCTUA_DATA_DIR` >= 2.5x the summed mailbox sizes (raw source and every attachment are written with no eviction, `lib/mail/syncMessageSanitizer.ts:44-58`); env `IMAP_CREDENTIALS_STORAGE=db`, `IMAP_SECRET_KEY` >= 32 chars, `SESSION_SEAL_KEY` >= 32, `TRUSTED_PROXY_HOPS=1` behind one Caddy (`lib/rateLimit.ts:86-99`), `NOCTUA_MAILBOX_WATCHER=1`, `NOCTUA_MAX_SYNC_WORKERS`, `NOCTUA_IMAP_LOGIN_HOSTS` only if IMAP login survives; proxy body limit >= 40 MB (attachments travel base64 in JSON, `smtp/send/route.ts:31,46-52`, no size guard anywhere, `next.config.ts` sets none); systemd timer doing `VACUUM INTO` of `mail.db` and `db/accounts/*.db` to the NAS with N generations, secrets backed up offline, restore drill; nightly imapsync/mbsync archive of all netcup mailboxes to the NAS (same tool as step 4).
4. **Migrate MailPlus -> netcup with imapsync on the LAN, one mailbox at a time.** `--justfolders --dry` per MailPlus login to learn the NAMESPACE/shared layout (unverified externally); migrate each shared mailbox from its owner login, `--exclude` the shared prefix on personal runs; `--useheader Message-Id --addheader --syncinternaldates`, no `--delete*`, `--f1f2 'Sent=<netcup Sent path>'` (same for Drafts), `--subfolder2`/`--f1f2` for filter-only mailboxes; second run must transfer 0; dedup on the server (Noctua shows two UIDs with one Message-ID twice, `lib/db/messages/upsert.ts:295-300`, `lib/messageCopies.ts:9-33`); verify exactly one folder per mailbox has a name in `SENT_NAMES` (`lib/specialFolders.ts:22-35`), rename/merge any second one; MailPlus labels: move label hits into folders beforehand or accept the loss (topics are local-only).
5. **Create users and mailboxes in this order.** Start server -> read the admin invite code from the journal (`lib/db/schema.ts:690-694`) -> he signs up with a provider-independent credential and his personal mailbox -> he creates her user (generated password, forced change, `doc:283-285`) -> she signs in and adds her main mailbox herself via "Add a mailbox" so she is the owner (`app/api/accounts/route.ts:32-35`; there is no owner transfer, `doc:125-126`), likewise her two other own mailboxes -> the 8 shared mailboxes via `POST /api/admin/accounts` without owner, both as members with roles, SMTP credentials stored by a manager; set `account.settings.sync.maxIdleSessions = 1` on shared mailboxes if the measured limit is tight (`imap/stream/route.ts:54-57`).
6. **First sync per folder from the server shell**, while no browser has the account open and imapsync is not writing: `bun scripts/runSyncJob.ts '{"accountId":"<id>","folderId":"<id>:<path>","mode":"full","fullSync":true}'` for INBOX, Sent and every imported folder. The UI first sync is INBOX-full plus a 30-day window elsewhere (step evidence in §1), the parent kills a worker after 10 min without re-enqueue (`lib/syncJobs.ts:74,454-467`), and only `fullSync` payloads resume from `highestProcessedUid` (`lib/workers/runSyncJob.ts:55-59`).
7. **Verify counts**: MailPlus vs imapsync host2 counts vs `SELECT COUNT(*) FROM messages WHERE folderId=?` per shard (only after step 6; a mismatch means "sync not finished" first). `scripts/diagnoseSyncState.ts:27-66` covers INBOX only.

## 7. Refuted, unverified or uncertain claims

No finding was refuted outright; the verifiers corrected these analyst premises (corrected content used above):
- "`findSentFolder` checks SPECIAL-USE `\Sent` first": false, name-only (`lib/specialFolders.ts:128-134`).
- "Topics are IMAP keywords": false, shard-local with keyword sync as a TODO (`lib/topics/core.ts:53-60`).
- "The fresh-account full sync is account-wide": false, INBOX full + 30-day `recent` elsewhere (`useSyncController.ts:630-646,569-576`).
- "Unbounded `maxIdleSessions` is a household risk": the client never sends it (`useSyncController.ts:1184-1189,1337-1338`); hygiene only.
- "The two Dev mailboxes are indistinguishable": `accounts.name` is free text and the e-mail is shown (`TopBar.tsx:481-491`); order and grouping are the real gap.
- "12 workers at once happens today": only with the watcher, a bulk import or a future sync-all; upstream is bounded by active tabs.
- "The compose From value feeds Reply-To": it is normalised away (`buildSendPayload.ts:82-88`).
- "A reply appears only when someone opens Sent": the manual account-wide sync pulls it (`useSyncController.ts:666-724`), and post-send sync failures are reported, not silent.
- "Opening a reply creates a `\Draft`": only after the first edit plus 2 s debounce (`draftAutoSaveState.ts:21-44`).
- "Mark as spam is just a move": it also clears `$NotJunk`/`NonJunk` (`spam/route.ts:33-34,47-50`).
- "Admin-created user without password needs a new parameter": the generated-password + "Add a mailbox" path exists (`doc:283-285,663-664`).
- "imapflow needs UIDPLUS for a uid": it can derive one only when the target mailbox is selected, which the pooled connection usually is not; practically UIDPLUS is required.
- "A per-user default signature has no visible effect": it changes the button label (`ComposeMessageField.tsx:447`), not the body.
- "No grep hits for import/alias/Sent in the design": they occur (`doc:208,336,351,344,350,416,460`) but in unrelated senses.
