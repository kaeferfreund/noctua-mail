2. **Medium — Startup accepts a malformed provisioning uniqueness index** — `lib/db/authPolicy.ts:141`, design §3.1 (unique partial index on normalizedEmail for active provisioning states). `CREATE UNIQUE INDEX IF NOT EXISTS` accepts any existing index of that name; a non-unique replacement let two `reserved` operations for one email coexist. Fix: validate uniqueness, columns and partial predicate via SQLite metadata; replace transactionally or fail startup when conflicting data prevents repair; regression test.
3. **Medium — Combined provider/identity moves skip destination revocation** — `lib/db/authPolicy.ts:89`. The destination increment requires NEW.providerId='credential'; moving a credential account from user A to B while changing provider to OAuth advances only A (probe CREDENTIAL_TO_OAUTH_MOVE before [1,1] after [2,1]); with B's security-state row missing it committed instead of aborting. Fix: when userId changes and either side is a credential account, validate and advance both users atomically; test provider change + identity move in one statement.
