# Internationalization

Slice 1 establishes next-intl without locale routing. URLs stay unchanged; there
are no locale middleware rewrites. German (`de`) is the default and fallback;
English (`en`) remains available. Existing application copy is migrated in later
slices. German UI copy uses informal du throughout.

## Messages and identifiers

Use semantic message IDs, such as `Settings.language.label`, rather than English
sentences as keys. Namespaces follow the plan: Shell, Search, Reader, Compose,
Settings, Calendar, Auth, Collaboration, Admin, Errors, Notifications and Pwa.
Create namespaces only when used. `messages/de.json` is the type source in
`types/next-intl.d.ts`; `messages/en.json` must have the same nested key structure.
`lib/i18n/translator.ts` explicitly imports both catalogs for standalone tracing.
Use `useTranslations` in client components, next-intl's server APIs in RSCs, or
`getTranslator(locale)` for shared non-React callers.

Write complete sentences with named ICU parameters, plurals and rich-message
slots where needed. Never concatenate translated fragments. Branch on stable
enum/action/error codes, never on translated labels. Labels are distinct from
identifiers, including group IDs, reminder durations (store numeric minutes),
roles and action names. Keep keyboard bindings stable; translate descriptions.
German typography uses „…“, correct umlauts/ß, and a non-breaking space before
units (for example `5,5 MB`).

Never translate mail bodies, subjects, signatures, comments, user-created names,
or protocol identifiers (IMAP flags/keywords, MIME headers, search operators,
ICS property names, TZID, PARTSTAT, role/status codes or subject prefixes).
Later generated-correspondence work must distinguish application-owned template
text from user content and capture the locale when inserting a draft template.

## Resolution and changing language

`i18n/request.ts` resolves once per server render using the live Noctua session:

1. The nullable `users.uiLocale` personal preference (`de`, `en`, or null).
2. A validated `noctua-ui-locale` device cookie (`de` or `en`).
3. Accept-Language quality weights and regional base-language matches.
4. German.

`null` means automatic, so it continues down this chain. Choosing Automatic in
the selector also deletes the device override, allowing Accept-Language to apply.
An invalid cookie/preference is ignored. Equal quality preserves header order;
unsupported ranges and zero/invalid quality are ignored. Do not initialize locale
from navigator.language or localStorage after mount.

The root sends the same locale, messages and explicit `Europe/Berlin` time zone
to `I18nProvider`/`NextIntlClientProvider`, sets `<html lang>`, and localizes root
description metadata. Product branding and environment labels stay unchanged.
After login/logout, the successful identity fetch also notifies a layout-level
listener to refresh when the personal language changes, without remounting the shell.
The selector appears in the shared auth frame (login, TOTP, invite signup,
reset, enrollment and mailbox gate) and in personal Preferences. Signed-in
mailbox-gate and Preferences selectors use `PUT /api/auth/preferences`; anonymous
selectors use the device cookie. On restricted enrollment screens, a fixed personal preference hides the device
selector: the cookie cannot override it and enrollment cannot bypass MFA to
change the stored value. Cookie changes trigger `router.refresh()`,
which merges RSC props without keying/remounting the persistent client shell.
Do not add a locale key around MailClient or forms: selected mailbox, open thread
and compose draft must survive language changes.

The new column follows the additive master-schema migration and never changes
Better Auth `auth_*` tables. The endpoint reuses the active MFA session guard,
same-origin JSON check and auth response-header forwarding. It takes no user ID,
needs no selected mailbox, and follows switch-account's non-audited preference
pattern. `/api/auth/me` adds `user.uiLocale` in full and restricted identities;
its four mailbox states and existing fields remain unchanged.

## Formatting and tests

Shared `lib/i18n/format.ts` helpers select `de-DE` and `en-GB`, use 24-hour time
and an explicit display zone (default `Europe/Berlin`). Formatter caches include
locale, zone and options. Date options can preserve explicit presentation
overrides. These helpers do not yet replace existing formatting call sites.
Keep ISO timestamps, canonical `en-CA` date keys, native date-input values and
ICS values stable. Preserve UTC/TZID/all-day/floating calendar semantics. Later
relative-day/grouping work must use display-zone day boundaries, including DST.

DOM tests that reach an i18n consumer opt into `lib/i18n/testRender.tsx`, which
provides English messages and a test App Router context. Other tests keep their
existing render helper. Layout SSR tests run their narrow request-config mock
in isolated processes; endpoint/resolution tests use real synthetic auth data.
